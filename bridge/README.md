# Worker Bridge setup (GitHub Actions — free, no proxy needed)

The bypass runs on GitHub's Azure runners instead of Render's blocked IP.
One-time setup (~5 min), then paste-link just works:

1. **Create a classic PAT**: GitHub → Settings → Developer settings →
   Personal access tokens (classic) → Generate → scope **`repo`**.
2. **Render dashboard → linkbypass → Environment**, add:
   - `GH_REPO` = `Alex-Leo-Reeves/linkbypassor`
   - `GH_TOKEN` = the PAT from step 1
   - `BRIDGE_SECRET` = auto-generated by `render.yaml` (or set your own)
   - `RENDER_URL` = `https://linkbypassor.onrender.com` (already defaulted)
3. **Mirror `BRIDGE_SECRET` into GitHub**: repo → Settings → Secrets and
   variables → Actions → New secret `BRIDGE_SECRET` = same value as Render's.
4. Redeploy. New jobs dispatch `bypass-link` events; the runner executes
   `bridge/run_remote.py` (same proven Playwright flow) and POSTs back to
   `/api/bridge/result`. The UI polling picks up completion automatically.

Notes:
- Without these vars the app falls back to local Playwright (blocked on
  Render, fine on residential hosts).
- Free-tier Actions: 2,000 min/mo. One bypass ≈ 2–4 min → ~500–1,000 links/mo.
- Batch of 5 = 5 workflow runs; add `concurrency` grouping if abuse appears.
